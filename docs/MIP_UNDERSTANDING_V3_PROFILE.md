# MIP Understanding V3 Profile

Status: **CP-U2 CONTRACT — IMPLEMENTATION TARGET**  
Profile identifier: `MIP-1.0/UNDERSTANDING-V3-1.0`  
Upstream linguistic contract: `MATRIX_NLU_CONTRACT_V3`  
Repository: `MATRIXNEO23/assembling`

## 1. Purpose

This profile is the additive, versioned MIP boundary required to transport the frozen Matrix-NLU V3 linguistic evidence into Matrix Engine **without semantic loss**.

It exists because `MipClaimV1` and legacy `MatrixNluClaim` cannot represent all frozen V3 evidence. They remain compatibility surfaces and are not mutated in CP-U2.

Canonical direction after CP-U2/CP-U3:

```text
MatrixNluOutput V3
-> validated Understanding V3 adapter
-> MipUnderstandingV3Observation
-> downstream explicit projections / Context / Authority
```

This profile is linguistic evidence. It does **not** own truth, Authority, BeliefConfidence, Memory Admission, persistent consent/goal, RelationshipState, AffectiveState or behavior decisions.

## 2. Versioning

Profile:

```text
MIP-1.0/UNDERSTANDING-V3-1.0
```

The envelope carries both:

```text
nluContractVersion
nluContractFingerprintSha256
```

`nluContractVersion` must equal `MATRIX_NLU_CONTRACT_V3` for this profile.

The fingerprint is carried as evidence and validated as a lowercase 64-character SHA-256 hex string. CP-U2 does not hardcode one artifact fingerprint because the upstream contract descriptor may include versioned runtime parameters such as `maxReferentCandidates`; the actual validated runtime bundle must supply its own exact frozen fingerprint.

## 3. Compatibility strategy

```text
MipClaimV1
= unchanged legacy/downstream compatibility claim

MipUnderstandingV3Observation / MipUnderstandingV3Claim
= new canonical lossless V3 linguistic evidence profile
```

Rules:

1. no automatic V3 -> `MipClaimV1` conversion in CP-U2;
2. no automatic synchronization with root `TypedClaim`;
3. no removal of legacy DTOs in CP-U2;
4. any later projection into Authority input must be explicit, validated and tested in CP-U3/CP-A1;
5. the full V3 evidence remains available even if a downstream module consumes only a subset.

## 4. Observation envelope

`MipUnderstandingV3Observation` carries:

```text
profileVersion
nluContractVersion
nluContractFingerprintSha256
input
observationSourceId
speaker
observer
provenance

```

Required invariants:

- input is the complete observation text;
- observationSourceId is non-blank;
- provenance is generated by `ModuleId.NLU`;
- provenance.observationId is PRESENT and equals `observationSourceId`;
- mention IDs are unique;
- candidate IDs are unique;
- claim IDs are unique and preserve upstream V3 identities;
- `ctx:speaker` and `ctx:observer` exist exactly once with matching candidate kinds;
- candidate mention references resolve to the observation mention table;
- claim mention references resolve to the observation mention table;
- all role candidate references resolve to the bounded candidate table.

## 5. Mention and candidate model

### Mention

`MipUnderstandingV3Mention`:

```text
mentionId
span
entityType = PERSON | LOCATION
surfaceForm?
entityRef
```

`entityRef` preserves entity resolution separately from mention identity. An unresolved mention remains a valid candidate.

### Referent candidate

`MipUnderstandingV3ReferentCandidate`:

```text
candidateId
kind = CONTEXT_SPEAKER | CONTEXT_OBSERVER | MENTION | CONTEXT_ENTITY
mentionId?
span?
entityType?
entityRef
```

Rules:

- `CONTEXT_SPEAKER` uses stable ID `ctx:speaker`;
- `CONTEXT_OBSERVER` uses stable ID `ctx:observer`;
- `MENTION` requires mentionId/span/entityType and must match the referenced mention;
- context-only candidates must not fabricate mention spans;
- candidate identity remains distinct from resolved entity identity.

## 6. Exact V3 field state

MIP's ordinary `MipField<T>` intentionally does not retain a value for non-PRESENT states. Frozen V3, however, can carry a primary linguistic value such as `UNKNOWN` together with `fieldStatus=AMBIGUOUS` plus ranked alternatives.

Therefore this profile uses a dedicated evidence field:

`MipUnderstandingV3Field<T>`:

```text
value
confidence
fieldStatus = RESOLVED | UNKNOWN | AMBIGUOUS | NOT_APPLICABLE
alternatives[]
```

Alternative:

```text
value
confidence
```

This is an evidence carrier, not a second truth/authority field system.

Required invariants:

- all confidences are finite in `[0,1]`;
- alternatives preserve order supplied by the upstream decoder;
- alternative values are unique;
- AMBIGUOUS requires ranked alternatives;
- role AMBIGUOUS has primary `UNKNOWN`;
- role UNKNOWN has primary `UNKNOWN`;
- role NOT_APPLICABLE has primary `NONE`;
- role RESOLVED points to one concrete candidate ID.

## 9. Temporal evidence and anchor identity

`MipUnderstandingV3TemporalEvidence`:

```text
temporalId
span
metadata{}
```

`MipUnderstandingV3TemporalRelationValue`:

```text
relation
anchorRef?
```

Anchor references preserve the upstream opaque form:

```text
speech-time
context-reference
temporal:<temporalId>
claim:<claimId>
```

Relations requiring an anchor:

```text
BEFORE
AFTER
DURING
AT_REFERENCE
```

For these, absence or invalid identity is a contract violation.

`temporal:<id>` must resolve to temporal evidence in the same claim.  
`claim:<id>` must resolve to a claim in the same observation.

No wall-clock time is fabricated by this profile.

## 10. Structural and interpretation status

Exact registries:

```text
structuralStatus = VALID | INVALID
interpretationStatus = RESOLVED | AMBIGUOUS | ABSTAINED
```

Hard invariant:

```text
structuralStatus == INVALID
=> interpretationStatus == ABSTAINED
```

An INVALID or ABSTAINED claim remains visible as linguistic evidence/diagnostics but must never be silently collapsed into an ordinary resolved claim by downstream adapters.

## 11. Span invariants

All spans use `[start,end)` character offsets into the complete observation.

Rules:

- `0 <= start < end <= input.length`;
- sourceSpan is valid;
- subject/object/negation/temporal evidence spans lie inside the claim sourceSpan;
- each plural span list is internally non-overlapping;
- mention spans are valid observation-level spans;
- no first-span-only normalization is allowed.

## 12. Provenance

The profile reuses canonical MIP `ProvenanceRef`.

Required observation provenance:

```text
generatedBy = NLU
observationId = PRESENT(observationSourceId)
```

CP-U3 will bind runtime turn/session context and DiagnosticTrace. CP-U2 does not invent a second provenance model.

## 13. Forbidden ownership fields

The canonical Understanding V3 profile intentionally has no fields named or semantically equivalent to:

```text
worldTruth
memoryAdmission
authority
beliefConfidence
persistentConsent
persistentGoal
relationshipState
affectiveState
behaviorDecision
```

In particular:

```text
NLU/Understanding CANNOT self-grant WORLD_TRUTH
```

World truth remains owned by WORLD / downstream Authority resolution based on trusted provenance.
